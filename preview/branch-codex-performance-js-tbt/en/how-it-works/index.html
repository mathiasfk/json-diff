How it works

Start a comparison

Paste the two inputs you want to compare into the left and right editors, or drop a file into each editor. Check the format selected for each side, then select Compare. To explore the tool first, use load example below Compare. Format and Clear affect only their corresponding editor.

What the tool compares

The tool compares parsed values rather than the original lines of text. It ignores formatting, object property order and array item order, including in nested data. Duplicate array items still count. Objects in arrays are aligned using identifying fields or their content to make changes easier to inspect.

Read the result

The diff uses the left input as its reference: red marks removals and green marks additions needed to reach the right input. Different values appear as a removal and an addition, with the differing segment emphasized. This direction is a display convention; the inputs need not represent earlier and later versions. The result shows normalized data, so its order and formatting can differ from what you pasted. An equivalent result means no differences were found under these comparison rules; the original texts may still differ. Select Back to edit your inputs again.

Choose an input format

Each editor accepts JSON, JSONL or a limited subset of YAML. JSONL requires one complete JSON value per nonempty line; blank lines are skipped and the records are compared as an array, ignoring their order. If both sides use the same format, the result is displayed in that format. If the formats differ, the parsed values are compared and the result is displayed in JSON. Comments and original formatting are not preserved.

When order matters

This tool is useful for comparing API responses, configuration data and unordered collections. It is not suitable for checking changes to sequences, rankings or histories where position is meaningful: reordering alone produces no difference. Use an order-sensitive comparison for those cases.

Other limits

YAML support covers common mappings, sequences and simple flow collections; it does not implement the full YAML specification. For complex YAML, convert the documents to JSON with a full YAML parser before comparing. Numbers use JavaScript precision: very large integers can lose digits, so represent exact identifiers as strings. Large inputs can slow the browser or exceed available memory.

Examples

Same content

These inputs are equivalent: the keys and array items changed order, but the values and their counts are unchanged.

Left
{"a": 1, "b": [1, 2]}
Right
{"b": [2, 1], "a": 1}

Different values

The same field has different values: 10 on the left and 20 on the right. The comparison highlights the value difference even though the structure is the same.

Left
{"value": 10}
Right
{"value": 20}

Different counts

The value 1 occurs twice on the left and once on the right. Ignoring array order does not ignore how many times each value occurs.

Left
[1, 1, 2]
Right
[1, 2]
